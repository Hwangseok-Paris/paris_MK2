## 2. 소개·프로젝트 문구 정리 및 경력 데이터 반영

선행 조건: 1단계 자료 확인 완료.

현재 상태: 홈 자기소개까지 사용자 승인 후 사이트 코드·로컬 데이터 반영과 화면 검증을 완료했다. 공개 프로젝트 13건, 대표 5건, 홈 삼성전자 CIA → 오스템 → NH투자증권 순서를 적용했다. TASK-256은 운영 데이터 원본 확인이 남아 분석중으로 유지한다. 로컬 유효 설정은 USE_DB=false이며 설정된 DB의 읽기 연결은 ECONNREFUSED로 실패했다. DB 조회 성공 시에는 로컬 데이터를 합치지 않고 DB 행을 그대로 사용하므로 운영 DB를 쓰는 환경에는 별도 데이터 반영이 필요하다. 운영 DB 변경·배포는 수행하지 않았다. 사용자가 DB·배포는 나중에 진행하기로 했으므로 운영 후속으로 이연한다. 다음 우선 작업은 3단계 실제 콘텐츠 디자인안 검토이며 DB 작업은 그 선행 조건이 아니다.

대표 프로젝트 선정 현황 — 2026-11-05, 대표 5건 및 홈 3건·순서 확정:

완료 기준: 검색·공유 정보가 실제 페이지와 일치하고, DB 장애 및 배포 실패가 정상 상태로 오인되지 않는다. 정리 작업 후 참조와 빌드가 유지된다. 실제 운영 검증을 하지 못한 항목은 미검증으로 남긴다.

예상 대상: `src/app` 메타데이터, `src/app/api/projects/route.ts`, `src/lib/db.ts`, `Dockerfile`, `.github/workflows/deploy.yml`, 미사용 파일, `README.md`.

## 단계별 검증과 기록

- 자료·문구·시안 단계: 사실과 근거, 문구 승인 여부, 기존 데이터/화면과의 대응을 검토한다. 코드 검사를 수행한 것처럼 기록하지 않는다.
- 구현 단계: 변경에 맞춰 TypeScript 검사, lint, 기존 테스트, 프로덕션 빌드를 실행한다. 관련 없는 검사를 불필요하게 반복하지 않는다.
- 시각 검증: 최소 모바일 390px, 태블릿 768px, 데스크톱 1440px에서 변경 화면을 확인한다. 필요한 경우 더 좁은 화면과 짧은 화면도 확인한다.
- 핵심 흐름은 홈 → 프로젝트 상세, 필터, 직접 딥링크, 상세 닫기/뒤로 가기, 연락처 링크, 다크 기본 유지, 모바일 하단 메뉴다.
- 자동 테스트 추가는 새 프로젝트 데이터, 필터, URL 상태, DB 대체 동작 등 회귀 위험이 있는 변경을 중심으로 판단한다. 단순 스타일 값을 복제하는 테스트는 만들지 않는다.
- 각 단계 종료 시 변경 파일, 서비스 코드 변경 여부, 검증 결과, 미검증/보류 항목을 기록한다.
- 승인된 결정은 `docs/decisions.md`, 완료 작업과 후속 후보는 `docs/task-log.md`에 기록한다. 안정적인 구현 사실이 바뀌면 `docs/project-context.md`를 갱신한다.
